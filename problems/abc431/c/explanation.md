# abc431 c 解説まとめ

## 問題概要 (Robot Factory)
頭パーツが $N$ 個($H_1,\dots,H_N$)、胴体パーツが $M$ 個($B_1,\dots,B_M$)与えられる。
頭と胴体を1つずつ組み合わせてロボットを作り、頭の重さが胴体の重さを超えると
そのロボットは倒れてしまう(頭の重さ ≤ 胴体の重さ ならOK、同じ重さも可)。
各パーツは1回しか使えないとき、倒れないロボットを $K$ 体作れるかを判定する。

- 制約: $1 \le N, M \le 2\times10^5$、$1 \le K \le \min(N,M)$、$1 \le H_i, B_i \le 10^9$
- 出力: 作れるなら `Yes`、作れないなら `No`

## 公式解説のアプローチ
鍵となる定理: 「$K$ 体の倒れないロボットが作れるなら、**最も軽い頭 $K$ 個** と
**最も重い胴体 $K$ 個** を使い、軽い順同士でペアにする方法でも必ず作れる」。

これは交換論法(exchange argument)で証明できる。直感的には、頭は軽ければ軽いほど
どの胴体とも組みやすく、胴体は重ければ重いほどどの頭も受け止めやすいので、
「使うなら最も条件の良いパーツを使う」のが最適という考え方。

手順:
1. $H$、$B$ をそれぞれ昇順ソート
2. 最も軽い頭 $K$ 個($H_0,\dots,H_{K-1}$)と最も重い胴体 $K$ 個
   ($B_{M-K},\dots,B_{M-1}$)を取り出す
3. 両方とも昇順に並べたまま、$i$ 番目の頭と $i$ 番目の胴体をペアにして
   $H_i \le B_{M-K+i}$ が全ての $i$ で成り立つか確認する
4. 全て成り立てば `Yes`、1つでも破れば `No`

計算量は $O(N\log N + M\log M)$(ソートが支配的)。

## 実装(main.cpp)で採用したアプローチとの対応
`main.cpp` では公式解説の「$K$ 個だけ抜き出して1対1で比較する」方法ではなく、
**両方をソートしたあと二分ポインタで最大マッチング数を数える** 貪欲法を使っている。

```cpp
sort(H.begin(), H.end());
sort(B.begin(), B.end());
int head_idx = 0, body_idx = 0;
long long robot = 0;
while (head_idx < n && body_idx < m) {
    if (H[head_idx] <= B[body_idx]) {
        head_idx++; body_idx++; robot++;
    } else {
        body_idx++;
    }
}
cout << (robot >= k ? "Yes" : "No") << endl;
```

- 頭・胴体をそれぞれ軽い順に並べ、頭ポインタと胴体ポインタを先頭から動かす。
- 今見ている胴体が今見ている頭を支えられれば(`H[head_idx] <= B[body_idx]`)、
  その胴体をこの頭に使ってペア成立、両方のポインタを進める。
- 支えられなければ、その胴体は軽すぎて今の頭には使えないので捨てて
  (`body_idx++`)、次のより重い胴体を試す。
- こうして得られる `robot` は「作れる倒れないロボットの最大数」になる
  (各頭に対して使える最小限の胴体を割り当てる貪欲法で、二部マッチングの
  最大数を最小コストで達成する古典的なテクニック)。
- 最大数が $K$ 以上なら `Yes`。

公式解説の方法が「$K$ 個だけ抜き出して判定」する $O(N\log N)$ なのに対し、
`main.cpp` の方法は「全体の最大マッチング数を求めてから $K$ と比較」する
$O(N+M)$(ソート込みで $O(N\log N + M\log M)$)で、どちらも同じ結論に達する。
実は「最大マッチング数 $\ge K$」であることと、「軽い頭 $K$ 個・重い胴体 $K$ 個の
ペアが全部成立する」ことは同値になっている(どちらも上の交換論法から導ける)。

## まとめ
- 「一番厳しい条件同士(軽い頭・重い胴体)を比べる」か「貪欲に最大マッチング数を
  数える」かの2通りの解法があり、どちらも本質は同じ交換論法に基づく。
- 二部マッチングを最大化する場面では、**両方をソートして二分ポインタで
  貪欲に割り当てる** テクニックが定番(尺取り法に近い考え方)。
