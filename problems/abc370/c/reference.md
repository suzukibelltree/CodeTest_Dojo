# abc370 c 解説の材料

## 問題概要
文字列 S を文字列 T（同じ長さ、英小文字のみ）に変換する。1回の操作で「S のある1文字を書き換えて、その時点の S を配列 X に追加する」ことを S = T になるまで繰り返す。

求めるのは、以下を満たす配列 X:
1. **要素数が最小**（＝操作回数が最小）
2. 要素数が同じ配列の中で **配列として辞書順最小**（先頭から見て初めて異なる要素で比較）

制約: 文字列長 1〜100、S・T は英小文字のみ。

## 現状のコードの問題点
`main.cpp` は最小操作回数 `m`（S と T が異なる位置の個数）は正しく求めているが、2つ目のループが `i` を「文字列の添字」と「何回目の操作か」の両方として扱ってしまっており、単に**先頭から順に異なる位置を直す**だけになっている。これだと出力される配列が辞書順最小にならない（log.csv の note「辞書順に並べるのが分からん」の通り、辞書順最小にする規則がそもそも実装されていない）。

## 公式解説
URL: https://atcoder.jp/contests/abc370/editorial/10894

### 操作回数
S と T で異なる位置の個数を x とすると、最小操作回数は x。どの操作も必ず「S_i ≠ T_i な位置 i を選んで S_i を T_i に書き換える」形になる（それ以外の書き換えは無駄になる）。

### 辞書順最小にする方法（O(N^2)）
毎回、残っている diff（S_i ≠ T_i な位置）の中から次のルールで1箇所選んで書き換える。

1. **S_i > T_i となる位置が1つでもあれば**、その中で**最小の添字 i** を選んで書き換える（＝文字を小さくする変更を、できるだけ左側から優先する）
2. **S_i > T_i な位置が無ければ**（残り全部 S_i < T_i）、その中で**最大の添字 i** を選んで書き換える（＝文字を大きくする変更は、できるだけ右側から先に行い、左側の増加は最後まで温存する）

このルールを m 回繰り返すだけで辞書順最小な配列が作れる。各ステップで残りの N 文字を走査するので全体 O(N^2)（N≤100 なので十分高速）。

### 直感
- 先に文字を「減らせる」操作は早く（左から）やった方が、その時点のSがすぐ小さくなる。
- 文字を「増やす」操作は避けられないなら、できるだけ後回し＆右側から。左側の増加を最後に残すことで、それまでの中間状態の辞書順を最大限小さく保てる。

## 解き直し後のACコード
サンプル1（`afwgebrw` → `oarbrenq`）で、期待される8行の出力と完全一致することを確認済み。

```cpp
#include <bits/stdc++.h>
using namespace std;

int main()
{
    cin.tie(nullptr);
    ios::sync_with_stdio(false);

    string s, t;
    cin >> s >> t;
    int n = s.size();

    int m = 0;
    for (int i = 0; i < n; i++)
        if (s[i] != t[i]) m++;
    cout << m << "\n";

    for (int step = 0; step < m; step++)
    {
        int idx = -1;
        // 1. S_i > T_i な最小の位置があれば優先
        for (int i = 0; i < n; i++)
        {
            if (s[i] > t[i]) { idx = i; break; }
        }
        // 2. 無ければ S_i < T_i な最大の位置
        if (idx == -1)
        {
            for (int i = n - 1; i >= 0; i--)
            {
                if (s[i] < t[i]) { idx = i; break; }
            }
        }
        s[idx] = t[idx];
        cout << s << "\n";
    }
    return 0;
}
```

## 詰まったポイント
- 「辞書順に並べる」ができなかった
- 単に前から異なる位置を直すだけでは辞書順最小にならない
- ポイントは「小さくする変更は左優先／大きくする変更は右優先（＝左側の増加は最後まで温存）」という2段階のルールに気づけるかどうか
