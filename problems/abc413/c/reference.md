# abc413 c 解説の材料

## 問題概要（Large Queue）
空の整数列 A に対し、Q 個のクエリを順に処理する。

- タイプ1 `1 c x` : 値 x を c 個、列の末尾に追加
- タイプ2 `2 k` : 列の先頭 k 個を削除し、その合計を出力

制約：
- Q ≤ 2×10^5
- 1 ≤ c ≤ 10^9、1 ≤ x ≤ 10^9
- 1 ≤ k ≤ min(10^9, 現在の A の長さ)

列の長さは最大 2×10^14 に達しうるため、要素を1個ずつ持つ配列やキューでは処理しきれない（メモリ・時間ともに破綻する）。

## 公式解説
URL: https://atcoder.jp/contests/abc413/editorial/13405

**想定解法：ランレングス圧縮したキューで管理する**

要素を1個ずつ持たず、`(個数 c, 値 x)` のペアを単位としてキューに積む。

- タイプ1：ペア `(c, x)` をキューの末尾に push するだけ（O(1)）。
- タイプ2：先頭のペアから順に見ていき、
  - ペアの個数 `c` が残り削除数 `k` 以下なら、そのペアを丸ごと pop して合計に `c*x` を加算し、`k -= c`。
  - `c > k` なら、そのペアを `(c-k, x)` に更新して停止し、合計に `k*x` を加算。

**計算量：O(Q)**
タイプ1で高々 Q 個のペアしか生まれず、タイプ2の処理でペアは生成されてから一度しか（分割されて）消費されないため、ならし O(Q) で処理できる。

**実装上の注意**
- 出力の合計値は最大 10^18 程度になりうるので `long long` が必須（32bit だとオーバーフロー）。
- 現在の `main.cpp` は `c` 回の `push` をループで行っており、`c` が最大 10^9 で Q=2×10^5 クエリ分繰り返すと要素数が最大 2×10^14 に膨らみ、**MLE（メモリ超過）** になる。ここがランレングス圧縮が必要な理由。

## 詰まったポイント
- log.csv の記録：MLE（「メモリでエラー」）。
- 原因：要素を `c` 個そのまま queue に push していたため、列の実際の長さ（最大 2×10^14）分のメモリを確保しようとして破綻した。
- 対策：値を1個ずつ持つのではなく、`(個数, 値)` のペアで持つランレングス圧縮キューに切り替える必要がある。
