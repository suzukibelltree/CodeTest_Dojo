# abc389 c 解説の材料

## 問題概要 (Snake Queue)
ヘビの待ち行列に対し、Q 個 (1 ≤ Q ≤ 3×10^5) のクエリを順に処理する。

- **タイプ1 `1 l`**: 長さ l のヘビが列の末尾に追加される。頭の座標は「列が空なら 0、そうでなければ最後尾のヘビの頭の座標+その長さ」。
- **タイプ2 `2`**: 列の先頭のヘビが抜ける（列は非空が保証される）。
- **タイプ3 `3 k`**: 列の先頭から k 番目のヘビの頭の座標を出力（1 ≤ k ≤ 現在の列の長さ）。

l は最大 10^9、答えは 32bit に収まらないので **long long 必須**。

## 公式解説
URL: https://atcoder.jp/contests/abc389/editorial/11975

### 想定解法
ポイントは「ヘビが列に入る順番と抜ける順番が同じ」ということ。つまり、
- これまでに追加されたヘビの長さを `l[1], l[2], ...` として累積和 `S[i] = l[1] + ... + l[i]` を持っておく
- これまでに抜けたヘビの数を `m` とする

このとき、列の先頭から k 番目のヘビ（＝全体では m+k 番目に追加されたヘビ）の頭の座標は、
「それより手前にいる（まだ列に残っている）ヘビの長さの合計」なので

```
ans = S[m+k-1] - S[m]
```

で O(1) 計算できる。タイプ1・タイプ2も配列の末尾書き込み／カウンタ加算だけなので全体 **O(Q)**。

### なぜ普通のキューだと詰まるか
タイプ3が「先頭からk番目」を聞いてくるため、素直にdequeで座標を持たせて「先頭が抜けたら残り全員の座標をmだけ引く」を毎回やると O(Q) かかり、全体 O(Q^2) になって TLE する（詰まったポイントに書いた内容そのもの）。実際にはヘビを引く操作をせず、「抜けた分＝累積和の基準点をずらす」だけで済むのがこの問題の肝。

## 解き直し後のACコード
現在の `main.cpp` はこの想定解法通りに実装されており、変数名は異なるが対応は以下の通り。

- `vec` = 累積和配列 `S`（`vec[0]=0` から開始）
- `idx` = 追加されたヘビの総数+1（次に書き込む位置）
- `escape_idx - 1` = 抜けたヘビの数 `m`

```cpp
#include <bits/stdc++.h>
using namespace std;

int main()
{
    cin.tie(nullptr);
    ios::sync_with_stdio(false);

    int q;
    cin >> q;
    vector<long long> vec(q);
    int idx = 1;
    int escape_idx = 1;
    while (q--)
    {
        int num = 0;
        cin >> num;
        if (num == 1) // 長さ l のヘビが列の末尾に追加される
        {
            long long l;
            cin >> l;
            vec[idx] = l + vec[idx - 1];
            idx++;
        }
        else if (num == 2) // 列の先頭にいるヘビが列から抜ける
        {
            escape_idx++;
        }
        else // 列の先頭から数えて k 番目にいるヘビの頭の座標を出力
        {
            int k = 0;
            cin >> k;
            long long ans = vec[k - 2 + escape_idx] - vec[escape_idx - 1];
            cout << ans << endl;
        }
    }
    return 0;
}
```

サンプルでの検証（累積和の値は `[0,15,25,30,35,45,60]`、m=2 の時点で k=4 → `S[5]-S[2]=45-25=20`、k=2 → `S[3]-S[2]=30-25=5`）と一致し、想定解法と同一のロジックであることを確認済み。

## 詰まったポイント
- 普通のキューで解こうとするとタイプ3の入力で詰まる（先頭からk番目を都度O(n)で数えると全体O(Q^2)でTLE）
- O(Q^2)はだめ
- キューに見せかけて実は累積和を使う問題だった（「抜けた」操作を実際にシフトせず、基準点をずらすだけで表現する）

## 補足（要注意点）
`vector<long long> vec(q)` は要素数 q（有効添字は `0..q-1`）だが、タイプ1のクエリが q 回連続すると `idx` は最終的に `q` になり `vec[idx-1] = vec[q-1]` への書き込みで境界ぴったりに収まるものの、直前の反復では `vec[idx]`（`idx` が最大で `q-1` になるまでは範囲内）と `idx++` の増加タイミングに注意。もし全クエリがタイプ1なら最後の反復で `idx == q` の状態で `vec[idx] = ...` を実行しようとし、`vec[q]` は**範囲外アクセス**になる。今回のテストケースでは踏んでいないため AC したが、安全のため `vector<long long> vec(q + 1)` のように1つ余分に確保しておくのが望ましい。
