# abc408 c 解説の材料

## 公式解説
URL: https://atcoder.jp/contests/abc408/editorial/13165

### 問題概要
N 個の城壁(1..N)と M 個の砲台があり、砲台 i は城壁 L_i 以上 R_i 以下を守っている。
砲台を何個か破壊して「どの砲台にも守られていない城壁」を1つでも作りたいとき、
破壊すべき砲台数の最小値を求める。

### 想定解法(imos法/差分配列)
- 各城壁について「その城壁を守っている砲台の数」を数えると、
  最も守りが薄い城壁(=カバーしている砲台数が最小の城壁)を狙って
  その城壁を守る砲台を全部壊せば、その個数で必ず1つ城壁を裸にできる。
  逆に、それより少ない数の破壊では(どの城壁を選んでも)まだ誰かに守られてしまう。
  → **答え = 全城壁の中での「その城壁を守る砲台数」の最小値**。
- 素朴に「各砲台ごとに担当する全城壁のカウントを+1」すると O(N×M) で TLE。
- 区間 [L_i, R_i] への一様な +1 は、差分配列(imos法)で O(1) に落とせる。
  - `diff[L_i] += 1`, `diff[R_i + 1] -= 1` を全砲台分積む。
  - 左から累積和を取ると `diff[x]` が「城壁 x を守る砲台数」になる。
- 全体計算量 O(N + M)。

## 詰まったポイント
提出コード(`main.cpp`)には複数のバグが重なっていた。

1. **`L` と `R` を別々にソートしてしまっている。**
   ```cpp
   sort(L.begin(), L.end());
   sort(R.begin(), R.end());
   ```
   これをやると「砲台 i の区間は `[L_i, R_i]`」という対応関係(ペア)が壊れてしまい、
   ソート後の `L[i]` と `R[i]` はもはや同じ砲台のものではなくなる
   (=存在しない架空の区間を作ってしまう)。区間のペアを保ったまま処理する必要がある。
2. **imos の積み込みループが `n`(城壁数)回になっている。**
   ```cpp
   for (int i = 0; i < n; i++) // 本来は m (砲台数) 回のはず
   {
       diff[L[i]] += 1;
       diff[R[i] + 1] -= 1;
   }
   ```
   本来は M 個の砲台すべてを差分配列に反映する必要があるのに、ループの上限が
   `n`(城壁数)になっているため、`N < M` のサンプルでは半分近くの砲台の情報が
   無視されてしまう。
3. **デバッグ用の出力がそのまま残っている。**
   ```cpp
   for (int i = 1; i <= n; i++)
   {
       cout << diff[i] << " ";
   }
   ```
   本来出力すべきは答え1個だけなのに、`diff[1..n]` を全部標準出力に流してから
   最小値を出力しているため、出力形式自体が期待値と一致しない。

これらが重なった結果、サンプル1(`N=5, M=10`)で実行すると
`3 5 1 0 0 0` が出力される(本来は `3` のみ)。特に3個目のバグ(ループ上限の誤り)により
砲台の情報が半分しか反映されず、本来 `3` になるはずの最小値が `0` になってしまっている。

## 解き直し後のACコード

```cpp
#include <bits/stdc++.h>
using namespace std;

int main()
{
    cin.tie(nullptr);
    ios::sync_with_stdio(false);

    int n, m;
    cin >> n >> m;
    vector<int> diff(n + 2, 0);
    for (int i = 0; i < m; i++)
    {
        int l, r;
        cin >> l >> r;
        diff[l] += 1;
        diff[r + 1] -= 1;
    }
    for (int i = 1; i <= n; i++)
    {
        diff[i] += diff[i - 1];
    }

    int ans = *min_element(diff.begin() + 1, diff.begin() + n + 1);
    cout << ans << endl;
    return 0;
}
```

サンプル1で動作確認済み(出力 `3` が `sample-1-expected.txt` と一致)。
ソートを行わず、`L_i, R_i` を読んだその場で差分配列に積み込む形にしたことで、
区間のペア崩れが起きないようにしてある。
