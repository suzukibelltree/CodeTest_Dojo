### 問題概要
アクセス権限管理システム。`N`人のユーザーと`M`個のコンテストページがあり、`Q`個のクエリを順に処理する。

- `1 X Y` : ユーザXにページYの閲覧権限を付与
- `2 X` : ユーザXに**全ページ**の閲覧権限を付与
- `3 X Y` : ユーザXがページYを閲覧できるか判定 → `Yes`/`No`を出力

制約: `N, M, Q ≤ 2×10^5`

### 詰まりやすいポイント
「ユーザーごとに持っている権限をどう表現するか」がポイント。素朴に配列やvectorで持つと、クエリ3の判定に`O(M)`かかり、全体で`O(QM)`となりTLE（最大4×10^10回操作）。

### 解法

**ステップ1: クエリ1と3だけの場合**
各ユーザXごとに「閲覧可能なページ集合 $S_X$」を`set<int>`（または`unordered_set<int>`）で持つ。
- クエリ1: `S_X.insert(Y)` → `O(log M)`
- クエリ3: `S_X.count(Y)` → `O(log M)`
- 全体で `O(Q log M)` に収まる

**ステップ2: クエリ2への対応**
クエリ2が来るたびに`M`個全部を`S_X`に突っ込むと`O(M log M)`かかり非効率（クエリ2がQ回来ると全体で`O(QM log M)`になり得る）。

そこで各ユーザーに **フラグ $f_X$（全ページ閲覧可能か）** を追加する。
- クエリ2: `f_X = true` とするだけ → `O(1)`
- クエリ3: まず`f_X`を見て、trueなら即`Yes`。falseなら`S_X`に`Y`が含まれるかで判定

### データ構造
```cpp
vector<set<int>> s(n + 1);            // s[x] = ユーザxが個別付与されたページ集合
vector<bool> allAccess(n + 1, false); // f[x]
```

- `1 x y` → `s[x].insert(y)`
- `2 x` → `allAccess[x] = true`（このとき`s[x]`を`clear()`してメモリを解放してもよい。判定にはもう使わないので）
- `3 x y` → `allAccess[x] ? "Yes" : (s[x].count(y) ? "Yes" : "No")`

計算量は全体で `O(Q log M)`、メモリは各setへの挿入回数の合計が高々`Q`なので`O(Q)`に収まる（`M`分の配列を全ユーザー分確保する必要はない）。

### サンプル1でのトレース確認
```
5 5 10
2 2        → f[2]=true
3 4 4      → f[4]=false, s[4]に4なし → No
1 1 1      → s[1]={1}
1 4 1      → s[4]={1}
1 4 2      → s[4]={1,2}
1 2 4      → s[2]={4}（f[2]=trueなので無意味だが問題なし）
3 3 2      → f[3]=false, s[3]空 → No
3 5 4      → f[5]=false, s[5]空 → No
3 2 1      → f[2]=true → Yes
```
出力: `No No No Yes` → 期待値と一致 ✅

### 実装のポイント（詰まりどころの回避）
1. `1 X Y`が重複しても`set`なら自動で重複除去される（`insert`は既存要素があっても安全）。
2. クエリ2の後に来る`1 X Y`は無駄な処理になるが、正しさには影響しない（`f_X`が優先されるため）。気になるならクエリ2到達時に`s[X].clear()`してメモリ節約してもよい。
3. 配列(`vector<bool>`長さM)をユーザーごとに持つのはNG（メモリ`O(NM)`で確実にMLE）。`set`/`unordered_set`のように**実際に付与された分だけ**メモリを使う構造を選ぶのが鍵。
